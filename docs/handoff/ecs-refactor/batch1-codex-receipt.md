## 与原任务单不一致之处

1. `batch1-verify.md` §1.2 要求拒存退出后仍调用 `FinishExitAfterPersist`。未照做:拒存没有最终落盘证据,销毁实体 / 写释放标记会丢失内存状态。实际保留退出实体、意图及原快照,等待后续处理;交接 / 回滚保留相应冻结状态。此处遵循权威三类规则与 AGENTS §7、§11.3 的数据一致性要求。
2. 内部枚举名为 `SaveResult`（`kQueued / kAlreadyPersisted / kHandoffAlreadyRequested / kRejected / kCount`）,语义对应任务单四种结果。`kQueued` 避免把异步入队写成已经落盘。
3. §1.3 及附录早期自述允许 AOI / 场景空表预挂,并把 Buff / 冷却 / 上下文当成必需组件。按后续确认的三类规则改为实际写入口延迟创建,不恢复这些旧口径。派生投影仍在初始化时创建。
4. Builder 的错误返回已由后续代理加入;全部 RPC 调用跟随当前 uint32 契约处理结果。属性缺背包的旧测试不再把缺组件解释为“没有装备”,改为拒绝 / 不重算,成功夹具补成已加载形状。
5. 按负责人的后续指令,原任务单的构建、测试和生成验证步骤均暂缓。
