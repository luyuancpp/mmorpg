# ECS 设计规则

职责、依赖与测试边界统一遵循根 [AGENTS.md](../../AGENTS.md) §11。本页三份语言副本使用同一规则。

- System 收口一类业务规则；玩法状态由 Component 或明确的状态所有者持有，避免隐式全局可变状态。
- Component 以数据为主；保持数据不变量所需的局部方法可以就近定义，不把网络、存储与跨域业务编排塞进组件。
- 允许职责明确的 System 进行单向业务编排，例如装备变化后请求属性系统重算；禁止循环依赖和底层对上层的反向依赖。
- 不为消除直接调用机械添加透传层。只有真实的策略变化、外部依赖或测试隔离需要时才引入接口。
- ECS 查询遵循 [ecs-component-access-rules.md](ecs-component-access-rules.md)：可选或跨实体组件用 `try_get`，每 tick 路径不补建组件。
- ECS 状态归所属 EventLoop；跨线程工作回到该 loop，生命周期与清理路径必须明确。单例组件不免除这些所有权约束。
